# 🔒 Безопасность Neurotask - AI Agents for Business

## Обзор безопасности

Данный документ описывает меры безопасности, реализованные в проекте Neurotask, включая аутентификацию, авторизацию, шифрование данных и защиту от уязвимостей.

## 🔐 Аутентификация и пароли

### Хеширование паролей

**Алгоритм:** bcrypt с 12 раундами соли

**Реализация:**
- Пароли автоматически хешируются при создании пользователя
- Пароли автоматически перехешируются при изменении
- Хеши имеют длину 60 символов
- Используется уникальная соль для каждого пароля

**Код реализации:**
```javascript
// В модели User (database-service/models/User.js)
userSchema.pre('save', async function(next) {
  if (!this.isModified('password')) return next();
  
  try {
    const saltRounds = 12;
    this.password = await bcrypt.hash(this.password, saltRounds);
    next();
  } catch (error) {
    next(error);
  }
});

// Метод для сравнения паролей
userSchema.methods.comparePassword = async function(candidatePassword) {
  return bcrypt.compare(candidatePassword, this.password);
};
```

### Валидация паролей

**Требования к паролю:**
- Минимальная длина: 6 символов (мягкая валидация)
- Рекомендуется: 8+ символов с буквами, цифрами и спецсимволами
- Проверка на фронтенде: длина, наличие заглавных/строчных букв, цифр, спецсимволов

### Безопасность сессий

**Сессии:**
- Используют express-session
- Хранятся в Redis (production) или памяти (development)
- CSRF токены для защиты от CSRF атак
- Автоматическое истечение сессий

## 🛡️ Авторизация

### Middleware аутентификации

**requireAuth:** Проверяет наличие активной сессии
**requireApiKey:** Проверяет валидность API ключа для межсервисного взаимодействия

### Роли пользователей

**Доступные роли:**
- `user` - обычный пользователь
- `moderator` - модератор
- `admin` - администратор

**Права доступа:**
- Пользователи могут изменять только свои данные
- Администраторы имеют доступ ко всем данным
- Модераторы имеют ограниченные права администратора

## 🔑 API ключи

### Генерация и хеширование

**API ключи для микросервисов:**
- Генерируются с префиксом `sk_`
- Хешируются с помощью SHA-256
- Хранятся только хешированные версии
- Plain ключи показываются только один раз при создании

**Пример:**
```javascript
// Генерация API ключа
const plainKey = 'sk_' + crypto.randomBytes(32).toString('hex');
const hashedKey = crypto.createHash('sha256').update(plainKey).digest('hex');
```

## 🌐 Защита от веб-уязвимостей

### CSRF защита

- CSRF токены для всех POST/PUT/DELETE запросов
- Проверка токенов на сервере
- Автоматическая генерация токенов при аутентификации

### XSS защита

- Helmet.js для установки security headers
- Валидация и санитизация входных данных
- Content Security Policy (CSP) headers

### SQL Injection защита

- Mongoose ODM для MongoDB
- Параметризованные запросы
- Валидация схемы данных

## 🔒 Шифрование данных

### Передача данных

- HTTPS в production
- TLS 1.2+ для шифрования соединений
- API ключи для межсервисного взаимодействия

### Хранение данных

- Пароли хешируются с bcrypt
- API ключи хешируются с SHA-256
- Чувствительные данные не логируются

## 📊 Логирование и мониторинг

### Безопасное логирование

**Не логируется:**
- Пароли (даже хешированные)
- API ключи
- Персональные данные пользователей

**Логируется:**
- Попытки входа (успешные/неуспешные)
- Изменения ролей пользователей
- Административные действия
- Ошибки аутентификации

### Мониторинг безопасности

- Отслеживание неуспешных попыток входа
- Мониторинг подозрительной активности
- Алерты при множественных неудачных попытках

## 🚨 Обработка инцидентов

1. **Немедленно** исправить уязвимость
2. Уведомить команду безопасности
3. Обновить документацию
4. Провести аудит безопасности

2. Сбросить все сессии
3. Требовать смены паролей

## 📚 Рекомендации по безопасности

### Для разработчиков

1. **Никогда не коммитьте** секретные ключи в Git
2. Используйте переменные окружения для конфигурации
3. Регулярно обновляйте зависимости
4. Проводите код-ревью с фокусом на безопасность

### Для администраторов

1. Регулярно меняйте API ключи
2. Мониторьте логи на предмет подозрительной активности
3. Используйте сильные пароли для административных аккаунтов
4. Регулярно обновляйте серверы

### Для пользователей

1. Используйте сильные пароли
2. Не передавайте учетные данные третьим лицам
3. Регулярно меняйте пароли
4. Включайте двухфакторную аутентификацию (если доступна)

## 🔄 Обновления безопасности

1. Анализ уязвимостей в зависимостях
